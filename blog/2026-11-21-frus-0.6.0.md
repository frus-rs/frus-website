The platform inside the page, a much larger widget set, and the tools around an application. A
frus page can now hold video, the camera, a web view and the platform's own views; an application
reaches purchases, storage, background work and more than one window; and `frus run` patches
every saved change into the running application by default.

<!-- truncate -->

## The platform inside the page

Video playback, the camera with code scanning, a web view on Android, Windows and the web, and
native views (an Android view, a Windows control, an element of the web page) drawn inside a frus page, all
through external textures that reach the GPU without a copy on Android. Custom fragment shaders
and GPU passes let an application draw what no widget does.

## What an application reaches

In-app purchases; network images cached on disk; a SQLite database with migrations; signing in
with PKCE; preferences and a secure store; haptic feedback and connectivity; opening an address
and the system's share sheet; permissions declared once in `Cargo.toml`. State is restored after
the system ends the process. Rust code can run with no window, scheduled by the system
(`main!(app, headless: { .. })`), and an application can open more windows than one, each listed
in its state.

## Widgets

Slivers; Material 3 widgets, the expressive ones included, and the Material motion system;
Apple-style widgets; new input and display widgets; `CommandPalette`, `HoverCard`, `ContextMenu`
and `ResizablePanels`; `BottomNavigationBar`; tabs with their own stacks; wheels that coast. A
widget can measure its children before placing them, and a component's own state rebuilds that
component alone, not the whole tree. State can be scoped to a subtree, where only its readers are
built again.

## Text and languages

OpenType features, variable font axes, a language per span and dictionary line breaking for Thai,
Lao, Khmer and Myanmar, in frus's own copy of cosmic-text, published as `frus-cosmic-text`. A
release build keeps only the glyphs the application can show: the counter's fonts go from 3.3 MB
to 607 kB. Translations and routes are checked by the compiler with the new `frus-macros` crate
(`messages!`, `#[derive(Routes)]`), and the framework's own words now come in German, Spanish,
Japanese, Thai and Vietnamese too. On Android, a text field has the system's spell checker and
"process text" applications.

## The web

WebGL 2 where there is no WebGPU, a canvas that fits a phone's screen and keyboard, safe areas and
a browser toolbar that follow the application, and real text on the page: find-in-page, printing
and search engines see what the application shows. `frus build web` now writes the site to deploy
to `target/frus-web/<package>/`, with the first screen's text in its HTML.

## Tools

Hot reload is how `frus run` runs: each save is patched into the running application on the
desktop, Android and the web, every state kept. DevTools shows the widget tree, the frames and the
log in the browser; `frus mcp` lets an AI agent drive the application; build modes, flavors,
values given at build time and release artifacts; `frus create --template package|plugin`;
several devices at once. There is a plugin for Android Studio and the other JetBrains IDEs, and a
new version of the VS Code extension. Every subsystem has a guide, and `LIMITATIONS.md` lists
every known limitation in one place.

## Lighter and faster

690 KB off every Android application, less work for a phone's GPU, and a transformed layer drawn
around what it holds instead of the whole screen.

## What breaks

`Edit` and `Status` have an `affinity` field, and `Widget::cursor_at` returns a `TextPosition`.
`PagePose` and `PageTransitionsBuilder` gained fields and variants, which breaks exhaustive matches
and struct literals.
[The changelog](https://github.com/frus-rs/frus/blob/master/CHANGELOG.md) has every entry.
